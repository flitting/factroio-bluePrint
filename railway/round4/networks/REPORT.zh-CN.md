# 第四轮：从零生成的环旁路与四象限定向网络

这一分支实际生成并运行了原四张蓝图之外的连接方案。几何来自独立直轨、90°曲线、对角直轨和坡道原语，未复制原四张蓝图的整条转向线路。主目标仍是吞吐，面积与寻路计算次要；本报告只汇报本分支，不宣布全项目冠军或全局最优。

## 实验边界

- Factorio Headless 2.1.25；base、quality、elevated-rails、space-age；正常品质1机头4空货车厢、核燃料、制动力1–7。
- 四方向各一条单向进线、一条单向出线，共8个外部端口；不把外部四轨扩容混入比较。定向网络在立交处把一进一出的中心偏移放到±17格，仍只有一进一出，全部过渡与内部轨道计入候选。
- 使用统一原生外部FIFO预置银行，无改速、无瞬移、无删除未完成请求。采用round4扩展地形协议；交通动作沿用经过等价性检查的旧协议。
- 短筛：S1均匀12 OD、seed17、每入口bank80、热身1800 ticks、计量3600 ticks。正式代表：bank150、热身3600、计量10800。短筛与正式试验的银行规模不同，不能把其差值单独解释为热身或稳态效应。

## 搜索范围与计数

- 57个已编码配置中，48个接受过原生观察（建造、轨道图或交通；验证层级逐项保留）；其余为未运行的派生信号配置或草稿。
- 当前完成31次上述短银行试验、2次正式窗口试验。
- 22个通过构建器的独立轨道几何，加上4个通过独立重建的短尾几何，共26个合法空间嵌入；另有14个不合法几何被原生建造排除。它们不是26种抽象拓扑。
- 三个主要连接家族：逆时针共享转向环（含直行、近转旁路与直行分层组合）；顺时针转向环（近转/直行旁路）；删去无用环段后的私有远转四象限网络。分流先后、汇流先后、私有缓冲长度与垂直嵌入另外记录。

所有配置、几何指纹、建造拒绝、原生图和交通证据见[candidate-inventory.json](candidate-inventory.json)。初期直轨方向0/8归一化造成的路径查找记录错误单列为工具问题，不当作新的设计失败。

## 怎样从新构型得到可运行蓝图

第一族把直行从转向环中拆出，再尝试近转旁路与NS跨线桥。原生A*检查暴露了一个容易误判的问题：最初近转旁路虽然存在，但比绕环近转稍长，空图列车仍选择环。因此“画出旁路”不能算实现分流，必须核对原生实际路径。

随后反转环的方向，让远转只需一段四分之一环；近转用增大对角段的90°弯、直行单独通过。四条远转选定路径不再需要环的其余部分，于是将那些环段删除，得到四条私有远转连接。保留完整顺时针环的版本也作为对照运行。

轨道合法性需要反复约束：最初下坡道覆盖了下一方向的地面分流曲线，原生重建丢失实体，方案被拒绝。将出口高架直段延长8或16格后解决。缩小时又出现远转高架弯与NS坡道重叠；把中央桥的高架半长收至18或20格，再用原生图确认EW穿越与坡道没有新的独立OD冲突。所有最终蓝图都经正常ghost建造，未用强制放置轨道跳过规则。

最小R35/n61短尾版是需要保留的负例：全局短窗仍有104列/分，但W→N在计量窗完成0列，待处理14列未减少，最后完成在tick1549。直到tick5400已至少64.2游戏秒没有W→N完成，而全局仍在前进。这提示共同出口的汇流竞争/饥饿，不能把它称为全网死锁或断轨；也说明独立OD冲突为0不能保证所有OD公平服务。本分支不推荐该配置。

## 删除端部直线的影响

四个短尾版本只删除地面直轨与随轨道移除的信号，保留所有曲线、分岔、汇流和坡道；原生独立核心重建、四侧严格两端口、12 OD与信号工作都复核通过。候选边界改至最外侧汇流后4格。

缩短的是四个方向的进、出公共直段：还会缩短首分流前的内部排队段，改变内部普通信号分段与固定fixture节距的接续。因此连通关系保持也不等于吞吐或队首阻塞不变。原长尾保留作对照。R75/n77、R59/n61和R35/n61的末端直线缩短40格；R35/n93缩短28格。统一首出口灯仍相对新端口为+8，但它相对最后汇流的实际距离随之缩短，所以储车与堵塞传播行为改变。短尾不是保持运营完全不变的“免费面积优化”，需要另外配对测试W出口关闭60秒后的恢复。详见[tail-trim-manifest.json](tail-trim-manifest.json)。

## 正式长窗口

正式结果只表示固定预置需求下的有限排空窗口；不是最大稳定到达率，也不是一般无死锁证明。短筛用过seed17，因此这里也不是独立留出验证。

| 配置 | 列/分 | 窗内12 OD | 损伤事件 | 外部银行始终非空 |
|---|---:|---|---:|---|
| r75-l17-n77-e16-h48 / 短尾 | 101.333 | 是 | 0 | 是 |
| r75-l17-n77-e16-h48 | 102.333 | 是 | 0 | 是 |

库存平衡复核：短尾完成304、进入306、测量平面间未完成33→35；长尾完成307、进入304、39→36。两者满足完成数＝进入数＋期初未完成－期末未完成。长尾完成多3列，但进入反而少2列，5列净库存变化足以改变这个有限窗口的排序，不能单凭102.333对101.333声称长尾稳态容量更高。60秒完成bins为短尾[100,103,101]、长尾[104,101,102]；已完成列车的平均穿越时间为19.81与21.92秒。这里库存位于入口与完成测量平面之间，不是AABB内的实体数量。完整定义与每OD间隔见formal-diagnostics.json。正式选择与对应原始证据由formal-selection-plan.json、formal-selected.json和formal-long-tail.json记录。其他种子、留出、配对出口堵塞及串行CPU计时由主研究流程统一选择复核。这里没有额外宣称CPU改善。

## 复现与文件

- `generate.py` / `build.py`：第一组环旁路几何与正常原生建造；`signal_variants.py`：环信号政策。
- `generate_clockwise.py`、`generate_compact.py`、`generate_refined.py`、`generate_orders.py`及各自build脚本：远转私有网络、紧凑化、合法性修复、分汇流顺序。
- `direct_signals.py`：生成普通信号对照；`trim_tails.py`：只删除末端直线。
- `round4/protocol/analyze_graph.py`：正常重建、信号、OD与冲突图；本目录各`*graph*.json`连接完整原生结果。
- `round4/protocol/run_bank.py`：统一FIFO银行测试；本目录各`*screen*.json`连接完整request/control/raw trace。
- `formal_selected.py`：按短筛最高吞吐、同分较小面积选取正式代表；规则保存在正式选择计划中。
- `index_results.py`、`analyze_orders.py`、`build_report.py`：重建候选台账、分汇流顺序和本报告。

所有最终蓝图同时保存在仓库`blueprints/r4-net-*.txt`和本目录。只把明确通过相应原生gate的版本加入推荐图册；未运行的派生配置、被拒绝的raw蓝图和诊断用孤立轨道probe不能当作已验证方案。
